# T08 제출 준비 점검표

- 작성일: 2026-10-15 (한국 표준시)
- 공식 과제·제출 화면: https://aleph-omega.vercel.app/cortex?panel=tasks
- 근거: `TASK-SOURCE.md`에 보존한 공식 카드와 사용자가 제공한 최신 제출 화면, 공통 가이드·제출 템플릿입니다.
- 현재 확인 범위: 카드 1·2의 로컬 시험 보고서와 증거를 대조했습니다. 운영 공개 URL, 실제 사용자 기기, 최종 제출 문안, 접수·승인은 이 점검표 작성자가 확인하지 않았습니다.
- 체크 원칙: 실제 조건을 충족한 근거가 있을 때만 체크하고 파일·URL·확인일을 함께 남깁니다. 아래 항목은 제출 준비 완료를 뜻하므로 모두 미완료로 시작합니다.

## 접수 조건과 과제 완주 기준

- [ ] 최신 제출 화면에서 **공개 결과물 URL 또는 PDF·DOCX·MD·TXT 보고서 한 파일 중 하나**라는 접수 조건을 다시 확인하고, 실제 제출 근거를 준비했습니다.
- [ ] T08-C01에 맞게 결과물 URL 필드에 공개 HTTPS URL 한 개를 제출했습니다. URL 준비만으로 제출 완료를 체크하지 않습니다.
- [ ] T08-C02에 맞게 소스 URL 필드에 HTTPS URL 한 개를 제출했습니다. 보고서 한 파일로 접수할 수 있어도 C01·C02의 완주 기준을 생략하지 않습니다.
- [ ] 소스 URL은 실제 확인한 `https://github.com/OWNER/REPO/commit/FULL_COMMIT` 형식이며, 소문자 전체 40자리 또는 64자리 커밋 해시를 사용했습니다. 예시·짧은 해시·브랜치·`/tree/` 주소가 없습니다.
- [ ] 제출하는 모든 URL을 새 시크릿 창에서 열어 계정 생성·로그인·인증·초대·비밀번호·OAuth·CAPTCHA 없이 접근되는 것을 확인했습니다. 결과물 첫 화면은 기존 공개 소개 페이지입니다. 심사자에게 비공개 영역 진입을 요구하지 않습니다.

## 설명서와 확인·판단 문안

- [ ] 인증 구현 설명서에 여섯 항목을 각각 나누어 작성했습니다: ① 무엇으로 붙였나, ② 왜 그걸 골랐나, ③ 어디를 어떻게 고쳤나, ④ 안 열리는 것을 확인한 기록, ⑤ AI와 나, ⑥ 아직 못 막은 것.
- [ ] 설명서 ①에는 실제 사용한 구현 방식과 이름이 있고, ③에는 등록·로그인·로그아웃·비공개 자료 조회 네 흐름의 실제 소스 위치가 있습니다.
- [ ] 설명서에 서로 다른 등록·로그인 질문 값과 저장된 공개키 실제 값·설명, 등록 요청 본문, 인증 상태 식별 방식이 연결되어 있습니다. C20·C22를 증거 보관만으로 완료 처리하지 않습니다.
- [ ] 설명서 ④에는 로그인 없이 열기·남의 패스키로 열기·질문 재사용·패스키 삭제 뒤 로그인의 네 확인이 모두 있으며 각 성공 요청과 거절 요청·응답을 나란히 연결했습니다.
- [ ] 설명서 ⑥에는 실제 남은 한계를 최소 하나 구체적으로 적었습니다. “없다”만 적지 않았습니다.
- [ ] 재현·통과 확인은 `어디로 가나요`, `무엇을 하나요(3단계 이내)`, `무엇이 보이면 통과`, `안 될 때`의 4줄이며, 실제 공개 심사 흐름으로 작성했고 1,500자 이내입니다.
- [ ] 판단은 `AI에게 맡긴 일`, `내가 판단한 일`, `AI 말을 안 들은 일`의 3줄이며 1,500자 이내입니다. 따르지 않은 제안이 없으면 실제 이유를 적었고, 사용자 판단을 만들어 쓰지 않았습니다.

## 파일·개인정보·증거 점검

- [ ] 업로드 파일이 최대 10개·합계 8MB 이하이며, 접수 필수 근거로 파일을 택했다면 PDF·DOCX·MD·TXT 보고서 한 파일 조건을 충족합니다. 업로드 직전에 최신 허용 형식·개수를 확인했습니다.
- [ ] 각 파일은 공통 가이드의 8MB 이하·빈 파일 금지·파일명 255자 이하 조건을 충족하며, 선택 증거를 임의의 필수 첨부물로 추가하지 않았습니다.
- [ ] 새 비공개 자료와 시험 계정은 가상 내용으로 표시했으며, 제출 문안·소스·증거·파일에 실제 개인정보나 비밀값이 없는지 검사했습니다. 기존 공개 내용 보존과 개인정보 기준이 충돌하는 부분도 확인했습니다.
- [ ] 세션·토큰·Cookie·Set-Cookie·Authorization 등 인증 비밀값이 공개 기록에서 가려져 있습니다. 개인키·비밀번호·비밀 API 키가 포함되지 않았습니다.
- [ ] 가상 인증기 자동 시험과 실제 기기 시험을 구분해 적었습니다. 실제 기기의 등록·취소·저장 위치·두 패스키 사용 결과를 자동 시험으로 대신해 완료 표시하지 않았습니다.
- [ ] `CRITERIA.md`의 공식 기준 47개를 모두 대조하고, 각 실제 결과에 증거 경로를 연결했습니다. 미검증·실패·제출문 대기 항목을 따로 표시했습니다.

## 운영 배포·접수·승인 상태

- [ ] 운영 배포에서 공개 소개·패스키·비공개 자료·로그아웃·키 삭제 동작을 확인하고, 검증한 소스 커밋과 배포 코드가 일치하는 것을 확인했습니다. 로컬 시험을 운영 배포 검증으로 표시하지 않았습니다.
- [ ] 제출 입력값·파일과 실제 접수 결과를 확인하여 기록했습니다. 제출 문안 작성이나 URL 준비를 접수 완료로 표시하지 않았습니다.
- [ ] 강사·마스터 승인 등 공식 승인 상태를 실제 화면에서 확인하여 기록했습니다. 접수 가능·접수 완료·과제 완주·공식 승인을 서로 다른 상태로 관리했습니다.
