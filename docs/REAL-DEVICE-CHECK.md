# 실제 기기 확인 — 사용자 등록·삭제 후 로그인 확인

운영 주소는 https://skt-aleph-project-1.vercel.app/#private-space 입니다. 공개 소개를 읽는 심사자는 이 확인을 수행하지 않습니다. 이 절차는 소유자가 실제 패스키를 확인하기 위한 것입니다.

사용자는 현재 대화에서 “구글 비밀번호 관리자 로그인 성공”, “패스키 2개 등록 → 1개 삭제 → 남은 키 로그인까지 성공했습니다.”라고 직접 확인했습니다. 근거는 `verification/real-device-user-confirmation.json`입니다. AI가 직접 본 OS 화면이나 자동 시험 결과로 바꾸어 기록하지 않습니다. 실제 기기 등록 취소는 확인 응답을 받지 않았습니다.

PIN·생체인증·패스키 저장 선택은 사용자가 직접 완료합니다. PIN·계정 비밀번호·생체정보·DB 비밀값을 채팅이나 제출물에 적지 않습니다. 아래는 재현 절차이며 이미 확인한 등록·삭제·로그인을 반복할 필요는 없습니다.

1. `owner-demo`처럼 실제 이름·이메일이 아닌 가상 별칭과 `내 기기`처럼 구분할 수 있는 패스키 이름을 적고 **처음 패스키 등록**을 누릅니다. 기기 등록 창에서 한 번 취소하면 취소 안내가 나오고 새 등록이 저장되지 않아야 합니다. 다시 등록을 완료하면 가상 자료 3개와 패스키 이름·등록 날짜·서버 공개키를 볼 수 있어야 합니다.
2. 로그인 상태에서 패스키 이름을 `예비 기기`로 바꾸고 **패스키 하나 더 등록**을 누릅니다. 잃어버렸을 때를 대비할 수 있도록 가능한 경우 별도 기기나 보안 키를 선택합니다. 같은 동기화 보관함의 두 항목만으로 독립된 복구 수단이 확보되었다고 단정하지 않습니다. 각 등록 창에서 직접 확인한 저장 위치를 기록합니다.
3. 패스키 목록에 두 개가 있는지 확인하고 하나만 삭제합니다. **로그아웃**한 뒤 같은 별칭과 남은 패스키로 로그인합니다. 남은 키로 가상 자료 3개가 다시 보이면 이 확인은 통과입니다. 실제 계정의 마지막 키는 이 절차에서 삭제하지 않습니다.
4. 새로고침하기 전에 **과제 확인 기록 보관**을 펼쳐 직접 확인한 저장 위치를 선택하고 **이 탭의 확인 기록 내려받기**로 실제 요청·응답을 보관할 수 있습니다. 화면이 기록하는 저장 위치는 사용자의 직접 선택이며 자동 검증값이 아닙니다. 새로고침하면 이 탭의 기록은 초기화됩니다.

확인된 사용자 결과: 구글 비밀번호 관리자 사용 / 패스키 2개 등록 / 하나 삭제 / 남은 키 로그인 성공입니다. 취소 안내의 실제 기기 확인은 아직 없습니다. 이 파일의 절차 전체나 자동 시험을 사용자가 실제로 완료한 기록으로 바꾸지 않습니다.
