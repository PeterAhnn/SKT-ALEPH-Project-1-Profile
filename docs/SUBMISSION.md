## 재현·통과 확인 4가지

아래는 **T08 운영 배포 후 공개 심사용 초안**입니다. 현재 운영 주소는 기존 소개만 공개되고 T08 영역은 없으므로 아래 기대 결과를 아직 충족하지 않습니다. 미리보기는 Vercel 로그인 페이지이며 앱의 503 응답은 관찰하지 않았습니다. 운영 반영 뒤 다시 검증해야 합니다. 심사자는 새 계정이나 패스키를 등록하지 않습니다.

어디로 가나요: https://skt-aleph-project-1.vercel.app/ (T08 배포 확인 전 후보 주소입니다.)

무엇을 하나요(3단계 이내): 1) 공개 소개 페이지를 엽니다. 2) 기존 소개 내용을 읽습니다. 3) 아래의 “나만의 공간”과 잠금 안내를 확인합니다. 계정 생성·패스키 등록은 하지 않습니다.

무엇이 보이면 통과: 기존 공개 소개가 그대로 열리고, 별도 비공개 공간은 잠겨 있으며 실제 비공개 자료가 보이지 않습니다. 인증·계정 격리·삭제 시험 결과는 첨부 설명서의 가린 성공/거절 요청·응답으로 확인합니다.

안 될 때: 운영 설정이 없으면 “비공개 공간을 준비하고 있습니다. 잠시 후 다시 시도해 주세요.”라는 안내와 API 503이 나오도록 구현했습니다. 이 경우 운영 검증은 미완료입니다. 공개 소개도 열리지 않거나 잠금 경계가 없으면 제출 준비 상태를 확인해야 합니다.

내가 판단한 일: 기존 과제 1을 직접 수정하고 공개 내용을 유지하기로 결정했습니다. 카드 1~5 순서대로 진행하며 기준 47개를 모두 검증하고 단계별 증거 보고와 제출 요구사항 확인까지 하도록 승인했습니다.

## 제출 전 남은 일

- Vercel MCP 관리 읽기는 403이었으나 공식 CLI 대체 접근과 앱 커밋의 Git 자동 미리보기 READY를 확인했습니다. 미리보기는 로그인 보호가 있고 기존 운영은 T08을 반영하지 않았습니다. verification/deployment-access.json과 public-access.json을 구분해 확인합니다.
- 운영 DB SQL 사용자 승인·역할 적용·연결·전용 환경 변수와 T08 배포를 완료하고 실제 공개 주소를 검증해야 합니다. SQL 승인 답변은 아직 없습니다.
- 실제 사용자 기기의 등록·취소·저장 위치·두 키 사용·삭제 후 로그인을 기록해야 합니다.
- 공식 원문·추적표 47개 대조와 기계적 비밀값 패턴 검사는 통과했습니다. 실제 기기·운영 등 남은 기준과 전체 개인정보 범위를 별도로 점검해야 합니다.
- 고정 전체 커밋 소스 URL의 공개 200 접근은 확인했습니다. T08 결과물 공개 접근과 두 URL의 공식 입력·제출은 남아 있습니다.
- 실제 입력·파일 업로드·접수·공식 승인 결과를 각각 확인해 상태를 갱신해야 합니다.

이 파일을 작성한 것만으로 제출·완주·승인이 완료되지 않습니다.
