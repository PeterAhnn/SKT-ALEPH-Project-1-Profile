## 목표와 보존 범위

과제 1에서 만든 소개 페이지의 공개 내용과 기능을 유지하고, 새 비공개 영역만 패스키로 보호합니다. 첫 화면은 누구나 등록·로그인 없이 읽어야 합니다. 서버는 패스키 검증 후 발급한 인증 상태를 확인한 뒤에만 해당 계정의 비공개 자료를 내려 줍니다. 비공개 자료는 만들어 넣은 가상 내용으로 준비하며 실제 연락처·신분증 번호·제3자 개인정보를 넣지 않습니다.

작업 전 기준 커밋과 기존 공개 내용·기능을 비교 대상으로 확보합니다. 작업 후 공개 내용 보존을 파일 차이와 화면으로 확인합니다. 기존 공개 정보와 제출물의 개인정보 금지 기준이 충돌하는지는 실제 내용을 대조해 보고하며, 기존 공개 내용을 임의로 삭제하지 않습니다.

## 왜 이걸 하는가

비밀번호를 쓰지 않는 인증을 기존 공개 소개 페이지에 붙여 공개키·일회용 질문·서명이 수행하는 역할을 확인합니다. 기기 분실 대비와 계정별 자료 접근 제한까지 한 묶음으로 검증합니다. 공식 목적의 전체 원문은 `TASK-SOURCE.md`에 있습니다.

## 제출물

공식 과제 제출물은 공개 결과물 주소, 소스 주소, 인증 구현 설명서 6항목, 짧은 확인 방법 4줄, AI와 내 판단 3줄입니다. 심사자는 공개 소개까지만 확인하며 잠긴 자리를 열지 않습니다. 비공개 자료와 패스키 검증은 제출문에 남긴 안전한 기록으로 설명합니다.

최신 제출 화면의 **접수 조건**은 “공개 결과물 URL 또는 PDF·DOCX·MD·TXT 보고서 한 파일 중 하나가 필수”입니다. 카드 5의 **완주 기준** T08-C01·C02는 결과물 HTTPS URL과 소스 HTTPS URL을 각각 한 개 제출하는 것입니다. 파일 한 개로 접수할 수 있다는 이유로 두 URL의 완주 검증을 생략하지 않습니다.

## 단계별 해야 할 일과 남길 것

각 작업 스텝은 카드 순서대로 진행합니다. 매 단계에서 수정한 파일·수행한 검증·남긴 증거·미완료를 보고하고 기준 추적표를 갱신합니다. 후속 단계가 필요한 기준은 그 사실을 밝히며 실제 증거가 생기기 전에는 완료로 표시하지 않습니다.

#### 첫 행동

## 인증 구현 설명서와 근거 연결

인증 구현 설명서는 공식 제출물입니다. 별도 PDF가 필수라는 요구는 없습니다. 실제 구현·시험 후 문서 본문을 작성하며 아래 여섯 항목을 유지합니다.

1. **무엇으로 붙였나:** 직접 구현·라이브러리·인증 서비스 중 실제 사용 방식과 이름을 적습니다.
2. **왜 그걸 골랐나:** 실제 선택 이유를 적습니다. 과제에서 특정 기술을 지정한 것처럼 쓰지 않습니다.
3. **어디를 어떻게 고쳤나:** 등록·로그인·로그아웃·비공개 자료 조회 네 흐름의 실제 파일·함수·경로를 연결합니다.
4. **안 열리는 것을 확인한 기록:** 로그인 없이 열기, 남의 패스키로 열기, 질문 재사용, 패스키 삭제 뒤 로그인 네 확인을 성공·거절 요청/응답과 나란히 적습니다. 공개키·서버 저장 값, 다른 질문 값, 가린 인증 기록도 연결합니다.
5. **AI와 나:** AI에게 맡긴 일, 사용자가 실제 판단한 일, 따르지 않은 제안과 이유를 적습니다.
6. **아직 못 막은 것:** 실제 남은 한계 최소 1개와 영향을 구체적으로 적습니다.

단계별 증거 화면·JSON·요청/응답 원자료는 검토·보관 자료입니다. 공식 요구의 설명서와 확인 기록에 연결하되 모두를 별도 필수 첨부물로 추가하지 않습니다.
