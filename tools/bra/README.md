# 자기소개 사이트 기록 갱신 장치

이 장치는 실제 리추얼·출석·제출 기록에서 숫자와 능력별 자기소개 문단 후보를 다시 만듭니다. Node.js 24와 표준 라이브러리만 사용하며 설치·로그인·API 키·외부 AI 호출이 필요하지 않습니다. 같은 입력 파일에서는 같은 결과를 만듭니다.

## 세 단계 실행 방법

1. 이 폴더를 새 폴더에 복사하거나 장치 ZIP을 모두 풉니다. `node --version`으로 Node.js 24를 확인합니다. `input`의 네 JSON을 실제 새 기록으로 갱신하고 모든 `asOf`를 같은 확인일 `YYYY-MM-DD`로 맞춥니다. 다른 사람의 이름·연락처·비밀값을 제외한 자료를 사용합니다.
2. 아래 생성 명령을 실행합니다. `last-result/candidates.md`에서 날짜·근거·사실과 공개 범위를 읽습니다. 본인이 승인한 후보 ID만 `input/approvals.json`의 `approvedCandidateIds` 배열에 적고 다시 실행합니다. 비워 두면 숫자만 생성하며 후보를 공개하지 않습니다.
3. 아래 검증 명령을 실행하고 `verification.json`의 `passed: true`를 확인합니다. 검토한 `last-result/data.json`만 기존 프로젝트의 `career/data.json`에 복사하면 사이트 숫자와 승인 문단이 바뀝니다. 기존 프로젝트 안에서는 `npm run bra:update`가 생성과 복사를 수행합니다. 공개 배포와 기존 자기소개 본문 수정은 별도 검토 후 수행합니다.

```powershell
node generate.mjs --input input --out last-result
node verify.mjs --input input --reference last-result --report verification.json
```

위 명령은 장치를 푼 폴더에서 실행합니다. 생성 명령을 먼저 실행하고 다음 검증 명령을 실행합니다. 검증기는 새 임시 폴더 두 곳에서 다시 생성한 네 결과 파일과 제공된 마지막 결과를 바이트·SHA-256으로 비교합니다. 임시 결과는 복구와 조사에 쓸 수 있도록 임시 폴더에 남깁니다.

## 입력 파일

| 파일 | 값과 규칙 |
|---|---|
| `rituals.json` | `asOf`, 날짜별 `days`, 선택적인 `screenTotals`와 `evidence`입니다. 각 날짜에 `open`·`close`를 모두 넣고 내용 항목 수 또는 공식 JSON의 문자열 배열을 사용합니다. `null`은 미저장, `0`·빈 배열은 저장됐지만 내용 없음입니다. 양의 정수·내용 있는 배열은 내용이 있는 기록 1회로 셉니다. 공식 JSON을 쓰면 확인일 `asOf`를 추가합니다. |
| `attendance.json` | 확인일·시작일·종료일, 재적·출석·결석·미확정일, 출석률 분자와 화면 표시율입니다. 현재 입력은 화면에 직접 표시된 45/46·97.8%입니다. 미확정일을 임의로 결석 또는 확정 출석으로 바꾸지 않습니다. |
| `projects.json` | `asOf`와 실제 `submissions` 행입니다. `id`, `submittedAt`(시간대 포함), `title`, `status`를 넣습니다. 동일 과제의 재제출 행은 보존하며 과제 수는 ID로 중복 제거합니다. |
| `approvals.json` | `asOf`와 `approvedCandidateIds`입니다. 현재 근거에 대응하는 ID만 허용합니다. 근거 문장을 바꾸면 ID도 바뀌므로 예전 승인을 새 문장에 재사용할 수 없습니다. |

현재 제공 입력은 2026-10-20에 인증된 공식 화면에서 확인한 날짜별 항목 수와 검토한 본인 행동의 최소 추출본입니다. 44일에 걸친 아침44·마무리43 저장 가운데 내용이 있는 기록은 아침44·마무리40으로 84회입니다. 8월11일·9월2일·9월16일의 빈 마무리는 내용 횟수에서 제외합니다. 미저장과 빈 기록은 구분합니다. 13주 과정 전체를 완료했다는 집계가 아닙니다.

리추얼 JSON 내보내기 완료 문구는 보였지만 최신 다운로드 파일을 로컬에서 확보하지 못했습니다. 그래서 최신 입력은 날짜별 화면을 직접 펼쳐 확인한 추출본이며, 다운로드 원본과 일치한다고 주장하지 않습니다. 과거 2026-10-15 JSON은 자기소개 사례 대조에만 사용했습니다.

문단 후보는 `evidence`에 넣은 날짜·아침/마무리·항목 이름·본인 행동을 사용합니다. 공식 JSON의 본인 일화·강점 실천·감사·본인에게 남긴 말도 읽습니다. 규칙에 따라 자기조절력·대인관계력·자기동기력으로 분류하며, 이는 문단 작성을 위한 해석이고 심리 검사 점수가 아닙니다. 새 기록에 해당 행동 문장을 넣으면 후보도 다시 생성됩니다.

## 결과와 공개 범위

- `last-result/data.json`: 숫자·출처·기간·승인된 문단만 있습니다. 사이트에 반영하는 파일입니다.
- `last-result/candidates.json`, `candidates.md`: 검토 전 후보와 근거입니다. 자동으로 사이트에 복사하지 않습니다.
- `last-result/manifest.json`: 입력 파일 네 개와 결과 세 개의 SHA-256입니다. 현재 시각·컴퓨터 경로를 넣지 않습니다.
- `verification.json`: 새 폴더의 두 실행 및 마지막 결과 비교 기록입니다.

공개 이메일은 지원 문서에서 사용자가 지정한 연락 수단입니다. 후보 생성기는 이메일·휴대전화 형식을 가리고 일부 비밀값 패턴을 거절하지만, 문장 속 모든 제3자 실명을 자동 판별하지는 못합니다. 새 입력·후보·승인 문단은 직접 읽어 확인합니다. 원본 리추얼 전체·비공개 소설·인증 DB·환경 파일을 사이트 또는 장치 ZIP에 넣지 않습니다.

## 실패했을 때

오류가 나면 확인일 일치 → 날짜 형식과 미래일 → 같은 날짜의 상충 기록 → 화면 합계 → 출석 분모·산식 → 승인 ID 순서로 점검합니다. 실제 원자료를 기대 수치에 맞춰 바꾸지 않습니다. 출석 분모가 0이면 출석률은 `null`이며 0%로 꾸미지 않습니다. 존재하지 않는 승인 ID는 과거 근거가 바뀐 경우일 수 있으므로 후보를 다시 검토합니다. 재현 비교가 실패하면 변경 전 입력과 결과를 보존하고 `manifest.json`의 차이를 확인합니다.

원래 사이트와 T08은 이 장치가 수정하지 않습니다. 장치 실행 후 후보를 채택하지 않아도 숫자와 후보 결과는 확인할 수 있습니다. 현재 제공 마지막 결과의 승인 문단은 0개이며 미승인 후보 7개는 공개 데이터에 포함하지 않았습니다.
