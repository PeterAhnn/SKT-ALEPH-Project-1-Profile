# 로그인 정책 비교 앱

이 앱은 로그인 방어 정책을 검토하는 사람이 요청 분포에 따른 공격 차단과 정상 요청 손실을 함께 비교하도록 돕습니다. T10 논문의 합성 요청을 브라우저에서 계산하며, 실제 서비스에 요청을 보내지 않습니다.

## 실행 방법

실행 ZIP을 받았다면 새 폴더에 모두 풀고 루트 `README.md`의 세 단계를 따릅니다. Node.js 24와 브라우저만 필요하며, 외부 npm 설치·계정·AI 서비스 키·환경 변수 설정은 필요하지 않습니다.

저장소에서는 프로젝트 루트에서 `node tools/brb/serve.mjs`를 실행한 뒤 `http://127.0.0.1:8013/`을 엽니다. 이 전용 서버는 `.env`·인증 DB·기존 소개의 비공개 자료를 읽지 않습니다. 포트가 사용 중이면 `node tools/brb/serve.mjs 8014`로 실행하고 주소도 8014로 바꿉니다.

## 사용자가 할 일 세 가지

1. 조건을 선택합니다. 합성 요청 분포와 개별 시드 또는 전체 시드, 한도와 시간 창을 확인합니다.
2. 정책 비교를 실행합니다. IP·계정·복합 기준의 공격 차단과 정상 요청 손실을 나란히 읽습니다.
3. 결과를 저장합니다. 저장한 파일에서 선택 조건과 지표, 합성 실험 범위를 확인합니다.

잘못된 값을 넣으면 수정 안내를 확인하고 조건을 고쳐 다시 실행합니다. 처음 방문한 사람이 설명 없이 이 세 행동을 할 수 있는지는 실제 사용자 확인 항목입니다. 자동 검사만으로 확인을 완료했다고 표시하지 않습니다.

## 논문과 데이터 범위

논문은 기존 사이트의 `../../paper.html`, 공개 MD는 `../../downloads/T10-paper.md`에 있습니다. 실행 ZIP에는 같은 공개 MD 사본을 `paper/T10-paper.md`로 넣고 전용 서버의 `/paper.html`에서 읽을 수 있게 합니다.

- 데이터 파일은 `data/paper-data.json`입니다. 논문의 원본 합성 요청 자료를 사용합니다.
- 요청 분포·시드별 결과와 전체 집계를 구분합니다. 합성 데이터의 식별자는 실제 이용자나 운영 기록을 뜻하지 않습니다.
- 논문은 각 제한 기준에 공통으로 한도 5회(주분석)와 10회(민감도 분석), 시간 창 60초를 적용합니다. IP에 5회·계정에 10회를 다르게 적용한 실험이 아닙니다. 이 설정은 해당 합성 실험 조건이며 운영 서비스의 권장 설정이 아닙니다.
- 화면의 한도는 5회 또는 10회이며 시간 창은 60초로 고정합니다. 직접 입력한 요청은 논문의 원래 시드·전체 집계와 구분한 별도 예시로 해석합니다.
- 계산은 브라우저에서 수행합니다. 외부 AI 호출·외부 대상 공격·로그인 수집·실제 이용자 자료 수집은 하지 않습니다.

## 직접 입력 JSON 형식

사용할 자료를 `직접 입력 · 예시 JSON`으로 바꾸면 1~500건의 JSON 배열을 입력할 수 있습니다. 실제 IP 주소·계정·실명·연락처·비밀값을 넣지 않습니다. 아래는 형식 예시이며 논문의 원본 요청이나 운영 관찰이 아닙니다.

```json
[
  {
    "timeMs": 0,
    "ipId": "syn-demo-ip-1",
    "accountId": "syn-demo-account-1",
    "actorLabel": "attack",
    "credentialValid": false
  },
  {
    "timeMs": 1000,
    "ipId": "syn-demo-ip-1",
    "accountId": "syn-demo-account-2",
    "actorLabel": "benign",
    "credentialValid": true
  }
]
```

| 필드 | 허용 값과 의미 |
|---|---|
| `timeMs` | 0 이상의 안전한 정수이며 단위는 밀리초입니다. |
| `ipId`, `accountId` | `syn-` 뒤에 영문·숫자·밑줄·하이픈 1~80자를 붙인 예시 식별자입니다. 실제 IP 주소와 실제 계정을 넣을 수 없습니다. |
| `actorLabel` | `attack` 또는 `benign`입니다. 합성 요청의 과다·정상 구분이며 지표 집계에만 사용합니다. |
| `credentialValid` | JSON 불리언인 `false` 또는 `true`입니다. 합성 자격 유효 표시이며 제한기 허용 판정에는 사용하지 않습니다. |
| `requestId` | 선택 항목입니다. 요청마다 중복 없는 1~160자 문자열을 사용하며 제어 문자를 넣지 않습니다. 생략하면 배열 순서에 따라 자동으로 붙입니다. |
| `originalIndex` | 선택 항목입니다. 0 이상의 안전한 정수이며 같은 시각의 판정 순서를 정합니다. 생략하면 배열 순서를 씁니다. |
| `runId` | 선택 항목입니다. 1~160자 문자열이며 제어 문자를 넣지 않습니다. 다른 `runId`는 독립된 제한기 이력을 사용합니다. 생략하면 하나의 실행으로 묶습니다. |

실행 묶음별로 시각과 `originalIndex` 순서로 정렬하고, 둘 다 같으면 원래 배열 순서를 유지합니다. 시간 창은 `(t−60,000, t]`이므로 정확히 60초 전 허용 이력은 만료합니다. 거부한 요청은 이력에 더하지 않습니다. 잘못된 형식이나 허용 범위를 벗어난 값은 안내를 보고 고친 뒤 다시 실행합니다. 직접 입력한 결과는 논문의 원래 수치 재현으로 표시하지 않습니다.

## 파일과 저장

`index.html`이 첫 화면이며, `engine.mjs`는 계산, `app.mjs`는 화면과 결과 저장, `styles.css`는 화면 표시를 담당합니다. 결과 저장 동작은 브라우저의 다운로드 기능을 사용합니다. 비밀값을 넣는 입력란이나 계정 설정이 필요하지 않습니다.

ZIP의 `SHA256SUMS`는 자신을 제외한 포함 파일의 SHA-256입니다. `file://`로 직접 열면 JSON을 읽지 못할 수 있으므로 README대로 HTTP 서버에서 엽니다. 파일이 없다는 안내가 나오면 압축을 모두 풀었는지 먼저 확인합니다.
