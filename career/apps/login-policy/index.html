요청이 모이는 방식

1~500건 · 시각은 0 이상의 정수 밀리초 · IP와 계정은 syn-으로 시작하는 예시 식별자를 사용하세요. 자세한 형식은 실행 안내에서 확인할 수 있습니다.

계산과 해석

이 결과가 말해 주는 범위

하나의 정책이 모든 상황에서 좋다고 결론 내리지 않습니다. 요청이 모이는 방식과 정상 이용 손실을 함께 살펴보세요.

어떤 규칙으로 계산하나요?

현재 시각을 t라고 하면 (t−60,000ms, t]에 허용된 요청만 셉니다. 정확히 60초 전의 이력은 만료합니다. 복합 정책은 IP와 계정을 각각 검사하고, 하나라도 한도에 도달하면 거부합니다. 거부된 요청은 이력에 더하지 않습니다.

정상·과다 라벨과 합성 자격 유효 여부는 정책 판정에 쓰지 않습니다. 정상·과다 라벨은 결과를 집계할 때만 사용합니다.

비율과 분모는 무엇인가요?

과다 요청 허용률 = 허용된 과다 요청 ÷ 전체 과다 요청 × 100입니다. 정상 요청 거부율 = 거부된 정상 요청 ÷ 전체 정상 요청 × 100입니다. 분모가 0이면 ‘계산 불가’로 표시합니다.

전체 30시드는 각 시드의 이력을 독립적으로 초기화한 뒤 건수를 합칩니다. 한 시드 결과를 전체 논문 결과라고 표시하지 않습니다.

실제 서비스에도 그대로 적용할 수 있나요?

이 앱은 합성 입력을 로컬에서 재생한 연구를 반영했습니다. 허용은 제한기 통과이며 로그인 성공이나 계정 침해 성공이 아닙니다. 이 비율은 운영 서비스의 오탐률이나 실제 공격 성공률을 추정한 값이 아닙니다.

다중 서버 동기화, 프록시 신뢰, MFA·계정 복구는 다루지 않습니다. 5·10회와 60초는 비교 설정입니다. 실제 적용 전에는 해당 서비스의 요청 분포와 정상 이용 손실을 별도로 확인해야 합니다.

자료와 실행 안내

T10 원본 합성 요청의 시각·순서를 보존한 자료를 사용합니다. 새 난수로 논문 결과를 대신하지 않습니다.

외부 API·분석 도구·계정 생성이 필요하지 않습니다. 입력과 결과를 서버로 보내거나 브라우저에 자동 저장하지 않습니다. 결과 저장 버튼을 눌렀을 때만 파일을 만듭니다.
